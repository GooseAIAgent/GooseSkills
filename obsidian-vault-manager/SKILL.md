# Obsidian Vault Manager

管理用户本地 Obsidian 仓库（本质是一个 Markdown 文件夹）。核心价值：把零散笔记连成网（Markdown 链接）、降低检索成本（摘要 / 标签 / 索引）、暴露结构问题（断链 / 孤立笔记）。

## 运行要求

- 使用 Python 3.9+，仅依赖标准库。
- macOS / Linux 使用 `python3`，Windows 根据环境使用 `python`。
- 脚本通过 `--vault` 接收仓库路径。
- 安装与完整用法见 [README.md](README.md)。

## 定位仓库

依次采用用户提供的绝对路径、Obsidian 应用配置中的 `vaults.<id>.path`、当前会话已确认的路径。配置文件位置：

- macOS：`~/Library/Application Support/obsidian/obsidian.json`
- Windows：`%APPDATA%\obsidian\obsidian.json`
- Linux：`~/.config/obsidian/obsidian.json`

多个候选无法确定时先确认目标；操作前核实实际路径，以实时文件系统为准。

## 授权与安全

- **默认只读**：交互式写入先提供清单或 diff，说明目标文件、链接或字段，经确认后执行。用户明确授权定期自动补链时，在该仓库和范围内沿用授权，每次保存含理由的清单后继续执行；授权不扩展到摘要、标签、MOC 或其他改写，也不替代文件访问权限。
- **排除范围**：扫描时跳过所有隐藏目录；除非用户明确点名，不读写 `.obsidian`、`.trash`、`.agents`、`.codian`、`.codex`、`.hinote`、`.smart-env`、`.cache`、`index.base`、`.DS_Store`、`Icon`、`Obsidian Attachments`。
- **敏感笔记**：文件 basename 匹配 `密码|password|token|secret|credential|私钥|凭据|api[_-]?key` 时不读内容、不摘要、不参与补链，报告只列文件名。处理中发现明显的账号密码或密钥清单，同样停止处理该笔记，标注“敏感内容，已跳过”。
- **修改边界**：保留未要求改动的原文、状态词和备注，不删除或移动笔记；frontmatter 只新增缺失字段。语义关联、摘要、标签和 MOC 由 AI 判断，脚本负责确定性处理。
- **先备份后写入**：用 `backup_vault.py` 或补链器内置逻辑备份本批次全部目标文件，确认备份完整后再写入。默认保留最近 3 个时间戳备份，可用 `--keep` 调整；只轮转符合 `YYYYMMDD-HHMMSS` 或 `*-YYYYMMDD-HHMMSS` 命名的备份目录，不清理用户自建目录。

## 操作规则

### 1. 扫描与诊断

运行扫描器；按需求汇总结构、孤立笔记、断链和同名笔记，呈现结论，不转储原始 JSON。统计含义和报告字段见 [扫描器说明](README.md#直接运行扫描器)。报告用于初筛，新增或修改链接仍需逐条验证。

### 2. 链接生成与修复

- **目标与格式**：只链接实际存在的笔记，新增链接统一使用 `[显示文字](相对路径.md)`；显示文字用目标 basename（去扩展名），同名笔记使用带目录的路径消歧。
- **语义依据**：围绕同项目、同系列、明确概念引用等具体主题分组，支持文件夹内和跨文件夹关联；文件名、标题、关键词或目录位置用于收集候选，每条候选须有理由。不确定的关联保留为建议，不为消除孤立状态强行补链。
- **数量与结构**：每篇每簇本次最多新增 3 条链接，单篇本次累计最多新增 8 条。成员 ≤4 且两两关系明确时可用 mesh 全互链；更大的组采用拆分或 hub 入口连接，入口也须遵守上述上限，不要求一轮连完。特定领域的分组规则按用户约定配置，不把演员、作者等个人分类习惯作为通用要求。
- **去重与写入**：检查源笔记已有的 Markdown 和 Wiki 链接，按实际目标路径去重。优先向已有“相关链接”区块追加；无该区块时在“相关改编”前插入或文末追加，避免重复标题及已有“相关版本”等区块中的链接。
- **路径编码**：以源笔记目录计算目标相对路径，将空格、`#`、`|`、`?`、`&`、`(`、`)` 编码为 `%20`、`%23`、`%7C`、`%3F`、`%26`、`%28`、`%29`；原始 `%` 先编码为 `%25`，避免重复编码。文件名中的 `#`、`|` 不使用 `\#`、`\|` 代替 URL 编码。
- **修复断链**：根据当前路径、basename 和笔记语境寻找正确目标。匹配不唯一或证据不足时保留建议；修复后核实目标存在。已有单向引用只是反向补链的候选依据，不机械地将全部引用改成双向。

### 3. 反链索引

Markdown 内部链接可以被 Obsidian 原生反链面板识别。只有用户明确要求显式索引时，才在笔记底部添加 `## 相关笔记`，列出来源笔记链接及一行说明；已有区块则合并去重。

### 4. 摘要与标签

基于全文为缺失字段生成 `summary`（一句话，≤50字）和 `tags`；遵守授权与安全规则，先展示“笔记 → 摘要 + 标签”预览。

```yaml
---
summary: 一句话要点
tags: [标签1, 标签2]
---
```

### 5. MOC 与索引

仅为实际存在的指定文件夹生成 `📇 <文件夹名> MOC.md`，包含标题、文件夹内全部笔记的链接和一句说明；不凭空创建分类。

### 6. 定期补链

配置或执行前读取 [定期补链与补跑规则](references/weekly-linking.md)，按其中的授权、状态记录、重试和恢复流程操作。

- 优先使用宿主调度工具，先查已有任务再更新，避免重复创建；没有可用工具时再考虑用户授权的系统级调度。
- 新任务应先明确仓库、首次到期、时区、状态文件、备份根和自动写入授权范围；这些配置保存在技能包外，不能继承别人的授权。
- 默认建议到期时间为每周一 13:00（`Asia/Shanghai`），每6小时检查是否到期且未完成；用户后续指定优先。
- 到期未完成才执行，成功后记录批次；失败不得标记完成，跨周漏跑合并一次。成功扫描且无可加链接也算完成。实际运行条件与通知规则见参考说明。

## 脚本速查

命令应从本次加载的 skill 目录执行，或使用该目录下脚本的绝对路径；不要假设项目工作目录就是 skill 目录。完整示例、报告说明和恢复方法见 [README.md](README.md)。

| 脚本 | 基本调用 | 关键条件与参数 |
| --- | --- | --- |
| 扫描 | `python3 scripts/scan_vault.py --vault <路径>` | `--out <文件>` 保存 JSON；`--include-sensitive` 仅在用户明确要求时使用 |
| 备份 | `python3 scripts/backup_vault.py --vault <路径> --files <相对路径…>` | 默认根为 `<home>/ovm-backups`；`--backup-dir <目录>`、`--keep 3` 可覆盖 |
| 补链执行 | `python3 scripts/linker.py --vault <路径> --plan <清单.json>` | 默认 dry-run；`--apply` 备份后写入；备份参数为 `--backup-root <目录>`、`--keep 3` |

补链清单为 JSON 对象，包含 `links` 数组；每条含仓库相对路径 `source`、`target`，关联理由 `reason` 和主题簇标识 `cluster`。示例见 README。无需修改脚本源码；默认 dry-run，经授权后加 `--apply`。脚本检查路径边界、敏感文件名与明显凭据、现存 Markdown/Wiki 目标去重、每簇 3 条和单篇 8 条上限，并备份、验证及记录结果。语义关联和未被简单规则识别的敏感内容仍由助手判断。

## 验证与交付

1. 写入后重新扫描，逐条检查本次新增或修复的链接目标，确认无新增断链；改动 frontmatter 时另行检查 YAML 合法性。
2. 验证失败时，依据本次备份仅恢复仍可确认属于本次写入的版本；遇到后续编辑或同步冲突，保留现场并说明需要处理的问题，不覆盖新内容。
3. 报告改动文件数、新增或修复链接数、摘要及标签写入数（如有）、备份位置和验证结果。扫描类任务直接呈现结构化结论；定期任务遵守参考说明中的安静与提醒规则。
