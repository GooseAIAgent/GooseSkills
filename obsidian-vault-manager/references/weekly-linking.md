# 每周补链与错过后补跑

## 配置与宿主要求

此文件只定义通用流程，不保存用户路径、任务 ID 或授权记录。执行前从用户明确指令、当前会话或宿主已有任务中取得配置；个人配置、状态与运行记录保存在技能包和 Git 仓库之外。

必需配置：目标仓库绝对路径、时区、周期与首次到期时间、检查频率、完成状态文件、备份根、保留数量及自动写入授权范围。可建议每周一 13:00（Asia/Shanghai）到期、每6小时检查、保留最近 3 份备份；用户设置优先。首次到期不能套用其他用户的历史日期。

没有明确仓库身份或写入授权时只读预览，先补齐配置。配置文件路径不存在时不得猜测其他仓库。既有会话或任务中的明确授权继续有效，不因技能升级要求再次确认。

优先查询并更新宿主已有调度任务，避免重复创建。没有原生调度工具时，可在用户授权后使用系统调度及实际可运行的 agent 入口。skill 不会自行注册任务或唤醒电脑；云端 agent 不能直接访问用户本机路径，需先配置可访问的仓库副本或挂载。

## 每次调度的判断

1. 先读取完成状态，按配置时区和周期计算最近一个已到期的批次（默认示例为北京时间周一 13:00），作为 `due_at`。首次到期之前直接结束。
2. 状态文件不存在时初始化；建议保存 `first_due_at`、`last_completed_due_at`、`completed_at`。损坏或含义不明时保留原文件并报告，不猜测完成状态后重复写入。
3. `last_completed_due_at` 已覆盖本次 `due_at` 时直接安静结束，只检查完成记录，不扫描仓库或重复补链。
4. 到期未完成时核实仓库身份、访问权限和运行条件。仓库改名后只有能确认是同一仓库才继续。无法执行则保留待执行状态，等下一次调度重试；权限或身份问题需要用户处理时报告，不绕过限制。
5. 无论漏过多少周，恢复后只针对当前仓库合并维护一次，成功后标记最新已到期批次。
6. 调度器不能提供原生补跑时，依靠每6小时检查：下次可执行的周期检查会尝试补跑，不保证开盖或启动应用后立即执行。每次检查结束就退出，不在同一次运行中轮询等待。

## 已授权的维护流程

1. 按主文件的安全规则扫描，优先分析新增或变更笔记，以及已有明确主题关联但缺少反向链接的笔记。已有单向引用是候选证据，不能据此机械地把所有引用变成双向链接。
2. 保存待加链接清单及每条理由。仅执行同项目、同系列、明确概念引用等高置信关联；主题不明的孤立笔记保留建议。只使用现存目标，URL 编码、同名消歧和去重沿用主文件规则。
3. 每篇每簇本次最多新增 3 条，单篇本次累计最多新增 8 条。只补充相关链接，保留正文和既有相关区块；不自动写摘要、标签或 MOC，不删除或移动笔记。
4. 用备份脚本备份本批次全部目标文件，确认备份完整后再写入。保存批次清单、原始版本和写入后版本的校验信息，以支持中断后判断实际完成程度。
5. 重扫，并逐条验证新增链接指向真实存在的目标，无新增断链。本次修改验证失败时，只恢复能够确认仍是本次写入版本的文件；文件已被用户或同步程序改动时保留现场并请求处理，避免覆盖后续编辑。
6. 扫描、必要的备份、写入和验证全部成功后，以临时文件加原子替换更新完成状态。成功扫描且无可加链接也标记完成。失败、中断、权限不足或回滚都不得标记成功。
7. 中断后再次执行，先核对批次记录和现有链接，跳过已经存在的链接并验证当前状态，再继续尚未完成的部分。避免并发处理同一批次。
8. 有实际改动时报告修改文件数、新增或修复链接数、备份位置和验证结果；无变化时保持安静。同一个未变化的问题只在首次发现或需要用户新操作时提醒。
