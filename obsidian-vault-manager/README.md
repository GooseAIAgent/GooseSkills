# Obsidian Vault Manager

让 AI 助手协助管理本地 Obsidian 仓库：扫描笔记结构、发现孤立笔记、检查链接，并为关联明确的笔记补充 Markdown 链接。

本项目由 **AI 操作说明和 Python 辅助脚本**组成。它不是需要安装到 Obsidian 中的插件：AI 助手负责语义判断，脚本负责扫描、按分组写入链接和备份。

## 可以做什么

| 能力 | 说明 |
| --- | --- |
| 仓库扫描 | 统计笔记、链接、字符量，列出孤立笔记、无入链笔记和同名笔记 |
| 链接检查 | 解析已有 Wiki 链接与 Markdown 链接，辅助定位断链与路径问题 |
| 关联补链 | 按同项目、同系列、明确概念引用等关系，为已有笔记建立链接 |
| 反向链接 | 对确有必要的关联补充反向链接，不把所有单向引用自动改成双向 |
| 摘要与标签 | 由 AI 生成预览，确认后补充缺失的 frontmatter 字段 |
| MOC 索引 | 基于已有文件夹和笔记生成导航页 |
| 定期维护 | 配合宿主调度工具执行每周补链，支持完成记录与错过后补跑 |

新增链接统一使用标准 Markdown 语法：

```markdown
[相关笔记](../项目/相关笔记.md)
```

扫描时兼容已有的 `[[Wiki 链接]]`，新增链接不使用该语法。

### 反链面板与显式索引

标准 Markdown 内部链接也能被 Obsidian 原生反链面板识别。若只需要查看有哪些笔记引用当前笔记，可直接使用原生面板；只有希望把来源列表保存为笔记正文、便于导出或跨工具阅读时，才需要额外生成“相关笔记”索引区块。参见 [内部链接](https://obsidian.md/help/links)和[反链](https://obsidian.md/help/plugins/backlinks)官方说明。

## 环境要求

- **Python 3.9 或更高版本**，建议使用 Python 3.10+。脚本仅使用标准库，无需安装第三方 Python 包。
- 一个可以访问本地文件、运行命令并加载 `SKILL.md` 的 AI 助手。具体技能目录和调用方式以所用助手为准。
- 一个本机可读取的 Obsidian 仓库；修改笔记时需要相应写入权限。

仅使用扫描和备份脚本时，不需要 AI 助手，也不需要启动 Obsidian。

> 脚本使用了 `list[Path]` 等类型注解，Python 3.8 不适合直接运行当前版本。

```text
obsidian-vault-manager/
├── README.md
├── SKILL.md
├── LICENSE
├── scripts/
│   ├── scan_vault.py
│   ├── backup_vault.py
│   ├── linker.py
│   └── vault_paths.py
└── references/
    └── weekly-linking.md
```

常见安装目录（将整个 `obsidian-vault-manager` 文件夹放入其中）：

| Agent | 用户级目录 | 项目级目录 |
| --- | --- | --- |

部分既有 Codex 环境使用 `~/.codex/skills/`，本地已能发现的安装可继续使用；具体以宿主当前版本文档和技能列表为准。完整技能文件夹应保留在一起，运行脚本时使用技能目录或绝对路径。

以上为格式与文档层面的兼容说明，未代表所有宿主及 Windows/Linux 环境都已实测。官方说明：[Agent Skills](https://agentskills.io/specification)、[Codex](https://learn.chatgpt.com/docs/build-skills)、[Claude Code](https://code.claude.com/docs/en/skills)、[Cursor](https://cursor.com/help/customization/skills)。其他 agent 需确认其支持此格式、文件访问及 Python 命令执行。

随后在对话中选择该 skill，并说明仓库位置。安装目录本身不是笔记仓库。

- [SKILL.md](SKILL.md)：供 AI 助手读取的执行规则。
- 本 README：供使用者阅读的安装、使用和维护说明。

## 快速开始

### 通过 AI 助手使用

可以直接提出以下请求，并将示例路径替换为自己的仓库路径：

```text
使用 obsidian-vault-manager 扫描仓库 /path/to/vault，汇总孤立笔记和断链。
```

```text
检查最近新增的笔记，为关联明确的笔记整理补链清单，列出每条理由，先给我预览。
```

```text
为“项目资料”文件夹生成 MOC 预览，只链接已经存在的笔记。
```

```text
为缺少 summary 和 tags 的笔记生成摘要与标签预览，保留已有字段。
```

未直接提供路径时，助手可按 [仓库定位规则](SKILL.md#定位仓库)读取 Obsidian 的应用配置或使用本次会话已确认的路径。存在多个候选仓库时，应先确认目标。

### 直接运行扫描器

以下命令均在本项目目录中执行。macOS / Linux 使用 `python3`；Windows 可根据实际安装情况改用 `python`。

```bash
python3 scripts/scan_vault.py --vault "/path/to/vault"
```

如需保存 JSON 报告：

```bash
python3 scripts/scan_vault.py --vault "/path/to/vault" --out "report.json"
```

扫描器兼容已有 Wiki 与 Markdown 链接，跳过 frontmatter 内的 Wiki 链接和围栏代码块中的示例链接；断链诊断主要针对笔记链接，不等于附件完整性审计。`--include-sensitive` 可以覆盖扫描器的敏感文件名及明显凭据过滤，只应在明确需要纳入这些文件时使用。

扫描不会修改笔记；`--out` 只会写入指定的报告文件，其父目录需要已存在。

JSON 报告包含 `stats`、`links`、`incoming`、`tags`、`orphans`、`no_incoming_links`、`broken_links`、`duplicates` 、`ambiguous_links`、`skipped_sensitive` 和 `files`；单篇笔记的字符量、修改时间及基础 frontmatter 字段信息可在 `files` 中查看。目录分布可根据文件相对路径汇总。

报告中的“孤立笔记”指无入链且无出链的笔记；当前脚本的“无入链笔记”统计有出链但无入链的笔记，与孤立笔记分开列出。“总字数”输出使用字符数统计，不是中文分词后的词数。

## 补链流程

通常先扫描，再由 AI 阅读相关笔记并形成含理由的候选清单。交互式写入经确认后执行，写入前备份，写入后重新扫描并检查新增链接目标。

补链遵循以下原则：

- 只链接仓库中真实存在、主题关系明确的笔记。
- 文件夹位置相同或关键词相似只能作为线索，不能单独证明相关。
- 每篇每个主题分组本次最多新增 3 条链接，单篇本次累计最多新增 8 条。
- 保留已有正文与相关区块，避免重复链接。
- 同名笔记通过目录路径消歧；路径中的空格、`#`、`|`、`?`、`&`、`()`、`%` 等字符需要正确编码。

小组成员不超过 4 篇且关系明确时，可以两两互链；更大的组采用主题拆分或入口笔记连接。入口笔记同样遵守每簇 3 条、单篇 8 条的本次新增上限，不要求一轮连完。

### 使用外部补链清单

`linker.py` 执行 AI 或维护者准备的 JSON 清单，不自行理解语义，不需要修改源码。清单中的路径相对于仓库根目录，统一使用 `/`；每条只代表一个方向，确需双向关联时分别列出。

在技能包和仓库之外保存 `plan.json`：

```json
{
  "links": [
    {
      "source": "项目/设计.md",
      "target": "项目/需求.md",
      "reason": "设计明确引用了该项目需求",
      "cluster": "项目需求与设计"
    }
  ]
}
```

先预览：

```bash
python3 scripts/linker.py --vault "/path/to/vault" --plan "/path/to/plan.json"
```

清单经授权后应用：

```bash
python3 scripts/linker.py --vault "/path/to/vault" --plan "/path/to/plan.json" --backup-root "/path/to/backups" --keep 3 --apply
```

脚本拒绝不存在、越出仓库、隐藏或排除目录内的目标，以及敏感文件名或含明显凭据的笔记；按实际解析目标检查已有 Markdown/Wiki 链接。已有 Wiki 目标有歧义时要求先处理，不猜测同名目标。单篇每簇最多新增 3 条、累计最多 8 条，超限则整批拒绝，需调整清单。

`--apply` 先备份全部修改文件，再追加相关链接，重扫并验证新增目标；失败时恢复仍与本次写入一致的文件，保留后续编辑冲突。零候选时不创建备份。`--keep` 必须至少为 1。

操作记录默认保存到清单旁的 `<清单名>.result.json`，也可用 `--report` 指定技能包和仓库之外的位置。同名记录已存在时自动添加唯一后缀，保留历史批次。记录包含清单、备份位置、前后校验值及验证结果，不包含笔记全文。清单、记录和备份应保留在本地。执行同一仓库时应由宿主避免并发；脚本的版本检查不能替代同步软件的文件锁。

## 定期补链与补跑

定期维护需要宿主提供调度能力。**复制 skill 文件夹不会自动创建定期任务，也不会唤醒电脑。**

例如，可以对助手说：

```text
为这个仓库设置每周一 13:00（Asia/Shanghai）自动补链。
授权在上述补链规则内自动执行，先备份后写入。
如果错过执行时间，在之后具备执行条件时自动补跑。
```

建议在任务中保存仓库位置、时区、首次到期时间、备份根、状态文件位置和自动写入授权范围。已有任务优先更新，避免重复创建。

补跑机制区分“到期时间”和“检查周期”：

1. 标准到期时间可以是每周一 13:00。
2. 优先使用调度器明确支持的漏跑补偿功能；否则每6小时检查一次是否有到期未完成的批次。
3. 未到期或本周已完成时直接结束，不重复扫描和补链。
4. 成功扫描、补链并验证后记录完成；确认无可加链接的成功扫描也算完成。
5. 失败、中断或权限不足时保持待执行，下一次具备条件的调度再尝试。
6. 跨过多周后合并维护一次，避免连续重复执行历史批次。

本项目约定每6小时检查一次，实际执行以调度器中保存的配置为准。周期检查意味着“下次可执行的检查时补跑”，不保证电脑唤醒后立即执行。

访问本机仓库时，执行环境需要保持运行，并具备文件权限；使用在线 AI 服务时还需要网络连接。笔记本合盖进入睡眠后，不能依靠此 skill 按时执行本地任务。

详细流程见 [定期补链与补跑规则](references/weekly-linking.md)。参考文件只定义流程；个人路径、任务 ID、首次到期和授权记录保存在技能包外，不能继承其他用户的配置。云端 agent 需要能够访问仓库副本或挂载，不能直接读取本机 iCloud 路径。

## 备份与恢复

单独备份指定笔记：

```bash
python3 scripts/backup_vault.py --vault "/path/to/vault" --files "笔记A.md" "项目/笔记B.md" --backup-dir "/path/to/backups" --keep 3
```

备份保留仓库内的相对目录结构。未指定备份根时，默认使用用户主目录下的 `ovm-backups/`，每次创建一个带唯一前缀的时间戳子目录，默认保留最近 3 版；`--keep` 至少为 1。部分文件备份失败时返回非零状态，不应继续写入。

恢复时，先对照本次操作清单和备份内容，再将需要恢复的文件复制回对应位置；如果文件已被后续编辑或同步更新，先比较差异，避免覆盖新内容。当前项目没有独立的一键恢复脚本。

## 隐私与操作边界

- 扫描器默认跳过隐藏目录、指定系统目录和按文件名识别的敏感笔记，具体名单见 [安全红线](SKILL.md#授权与安全)。
- AI 处理中发现明显的账号密码、密钥等内容时，应跳过该笔记。文件名过滤不能识别所有正文中的敏感信息。
- Python 脚本在本地运行；AI 阅读笔记并生成语义关联、摘要或标签时，相关内容会进入所用 AI 服务的处理流程。
- 日常操作默认只读。定期自动补链需要明确授权，该授权不扩展到摘要、标签、MOC 或其他原文改写。
- 技能说明中的授权不替代操作系统或宿主工具的访问权限。

## 使用限制

- 扫描器使用轻量解析，报告用于初步诊断。复杂 Markdown、同名链接和移动后的路径仍需复核；扫描结果为零断链不能替代逐条检查本次新增或修改的目标。
- frontmatter 的扫描属于基础字段提取，不是完整的 YAML 校验器。
- 补链器与扫描器共享目标解析；复杂 Markdown、Obsidian 别名属性、嵌套语法等不保证完整支持，仍需人工复核。
- 摘要、标签、MOC、语义补链及定期补跑属于 AI 工作流；Python 辅助脚本不会单独实现全部功能。

## 本地验证

在技能目录执行 `python3 -B -m unittest discover -s tests -v`。测试仅使用临时仓库，覆盖链接解析、敏感内容排除、上限、备份、重复执行与失败回滚；不扫描真实笔记。Windows 可改用 `python`。这不替代在各 agent 和操作系统上的实际验收。

将 skill 的操作说明、脚本及通用参考文档纳入版本控制，便于查看差异和恢复历史版本。

公开仓库前，将参考文档中的个人绝对路径、任务 ID 和授权记录替换为通用示例；笔记正文、扫描报告、运行状态和备份应保留在本地，不与 skill 一起发布。
