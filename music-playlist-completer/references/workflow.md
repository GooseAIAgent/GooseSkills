# 完整工作流详解

## 输入格式细节

### 网易云收藏歌单 CSV

网易云「收藏歌单」导出的 CSV 通常包含：歌名、歌手、专辑、时长（秒）、网易云链接（`https://music.163.com/song?id=NNN`）。`build_missing_list.py` 按列名模糊匹配（歌名/歌曲、歌手/艺术家、专辑、时长、链接/网易云链接/url），`id=` 自动提取为 `sid`。

### m3u8

- `#EXTINF:245,歌手 - 歌名` 后跟本地路径 → 视为本地已有；
- 后跟网易云链接 → 提取 `sid`，视为平台条目；
- `# [本地无]` 之类的注释行自动忽略。

### missing.json 条目格式（三个下载脚本的统一输入）

```json
{"t": "歌名", "a": "歌手", "alb": "专辑", "dur": 245, "sid": "186001"}
```

- `dur` 单位秒，是版本校验的核心依据，务必保留。
- `sid` 为空时 `netease_dl.py` 会跳过该条（只走 QQ 搜索兜底）。

## 本地库比对口径

- 主键：`norm("歌手 - 歌名")` 标准化（去空白/标点/括号注释、转小写）。
- 文件名格式假定为「歌手 - 歌名.flac」；无 ` - ` 的文件退化为「歌名」键。
- 注意 CSV 里自带的「本地文件」列常有历史错配（同曲不同版本），**不要直接采信**，以实际扫描结果为准。
- 化名歌手（群星、未知、佚名、网络歌手）不算真实歌手，QQ 宽松档只按「时长差 ≤3s」锁定。

## 统计与交付口径

一次完整补全后，向用户报告应包含：

1. **覆盖率**：`（本地已有 + 各平台成功下载）/ 歌单总数`。
2. **音质构成**：从 `下载记录.jsonl` 汇总 FLAC/320k/128k 数量与总体积。
3. **待人工确认清单**：`版本待核对.jsonl`（时长差 >3s）+ QQ `match != 精确` 的条目（核心名/同歌手）。
4. **未获取清单**：分三类——
   - 原版受限，仅他人翻唱可下（未下载，附候选）；
   - QQ 有曲目但无版权（需付费/数字专辑）；
   - 同歌手版本仅现场/重录。
   每条附 QQ 候选（歌手/歌名/时长/可用音质），来自 `qq_probe.py` 输出的 `QQ候选对照.csv`。

## m3u8 重建

路径全部变化后（如重新分类）必须重建并逐条校验：

```python
# 伪代码：先建索引（大小写不敏感），逐条 os.path.exists 校验后再写
idx = {}  # stem.casefold() -> abs path（递归扫描输出目录）
for x in playlist:
    p = x.get("local") or idx.get(safe(f'{x["a"]} - {x["t"]}').casefold())
    if p and os.path.exists(p):
        lines += [f"#EXTINF:{dur},{a} - {t}", p]
```

macOS 文件系统大小写不敏感但保留大小写，索引键用 `.casefold()` 防止「IU」vs「iu」这类漏配。

## 并发与时长预算

实测参考（千首量级）：

| 阶段 | workers | 速度 |
|---|---|---|
| 网易云直下 | 4–6 | 约 20 首/18s（FLAC 平均 30MB） |
| 网易云替代 ID | 3 | 每首含搜索约 2–4s |
| QQ 兜底 | 3 | 每首含搜索+多 mid 试 vkey 约 2–5s |

超过 500 首建议分批跑并保留 `.jsonl` 记录，重跑幂等。
